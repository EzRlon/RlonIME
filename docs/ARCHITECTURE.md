# RlonIME — 架构与实现说明

## 一、整体架构

系统分五层，层间通过明确的数据结构解耦，便于后续替换任意一层。

│               inserter.py (上屏)                           │

                            │ Candidate / Suggestion / SceneContext

### 与水杉输入法的关系

水杉输入法（Metasequoia IME）是基于 Windows 原生 **TSF** 框架的 C++ 自研输入法，
**不依赖 Rime 引擎**，因此不能加载 `.dict.yaml`。

本系统与水杉是**协作**而非嵌入关系：

```
RlonIME（本系统）                          水杉输入法
┌──────────────────┐                  ┌──────────────────┐
│ 场景识别          │                  │ TSF 文本服务 DLL │
│ 三级身份细分      │                  │ 系统级输入法      │
│ 621 条专业词库    │                  │ 全拼/双拼/五笔    │
│ 中英术语映射      │                  │ AI 联想           │
└────────┬─────────┘                  └────────▲─────────┘
         │                                     │
         │  msime_bridge.py 导出                │
         └─────────────────────────────────────┘
           ① zhiyu_quanpin_dict.txt    → 设置→词库→批量导入
           ② custom_translations.txt   → 数据目录，中译英
           ③ msime_ai_prompts.txt      → AI 辅助自定义提示词
```

详见 [MSIME_INTEGRATION.md](MSIME_INTEGRATION.md)。

## 二、场景感知的实现要点

### 2.1 三级识别策略

1. **进程名匹配**（置信度 0.9）
   `SLDWORKS.exe` → SolidWorks，`acad.exe` → AutoCAD，`DXP.exe` → Altium Designer

2. **文档后缀判定**（置信度 0.95）—— **最精确的信号**
   工程软件窗口标题通常形如 `SOLIDWORKS ... - [0917.SLDDRW]`。
   后缀直接决定场景，且**一旦命中即返回，不再叠加关键词**：

   | 后缀 | 场景 | 后缀 | 场景 |
   |---|---|---|---|
   | `.SLDDRW` | 工程图 | `.PcbDoc` | PCB 布局 |
   | `.SLDASM` | 装配体 | `.SchDoc` | 原理图 |
   | `.SLDPRT` | 三维建模 | `.dwg` | 工程图 |
   | `.SLDSM` | 钣金 | `.rvt` | BIM 建模 |

   这一设计解决了实测中发现的缺陷：早期版本用关键词匹配，导致
   `plan.dwg` 被同时判定为「工程图」和「BIM 建模」。

3. **关键词兜底**（无后缀时）
   匹配 `drawing` / `装配` / `原理图` 等词。

### 2.2 进程名冲突处理

`acad.exe` 同时属于 AutoCAD 与 AutoCAD Electrical。采用**显式优先级 + 首个登记优先**：

```python
priority = ["autocad", "cadence"]   # 通用软件优先占用进程名
ordered = sorted(softwares, key=...)
for sk, sdef in ordered:
    for proc in sdef.processes:
        self._process_index.setdefault(proc.lower(), sk)   # setdefault 保证不覆盖
```

避免通用 CAD 被误判为电气专用版本。

## 三、检索引擎的打分模型

### 3.1 四路匹配

| 匹配方式 | 基础分 | 说明 |
|---|---|---|
| `full_pinyin` | 100 | 全拼精确匹配 |
| `zh_prefix` | 95 | 中文前缀（用户直接打中文） |
| `prefix` | 88 − 多出字母数 × 9 | 拼音前缀，距离越近分越高 |
| `abbr` | 75 | 首字母简拼 |
| `en` | 70 | 英文片段反查 |
| `zh_contains` | 60 | 中文包含 |

### 3.2 加权项

```
总分 = 基础分
     + 领域匹配 (+20)
     + 场景标签匹配 (+30 × 命中数/2)
     + 软件匹配 (+10)
     + 词频 (freq/1000 × 0.35 × 100)
     + 历史使用 (次数 × 5，上限 40)      ← 有上限，防止无限膨胀
     + 自定义词条 (+50)
     + 跨领域修正 (工程图场景 +6 / 其他 −12)
```

**历史加成上限**是刻意设计：避免个别词条因长期高频使用而永久霸榜。

### 3.3 兜底补足

精确匹配时列表可能只剩 1 条。当结果少于 4 条时，
自动补入**同领域、同场景标签、高频**的相邻术语，
既避免候选窗大片空白，也便于用户顺手切换到相关概念。

## 四、中英术语映射（工程图核心）

### 4.1 数据结构

每条术语同时携带中英文与标准编号：

```json
{
  "zh": "沉孔",
  "en": "Counterbore",
  "standard": "GB/T 152.3",
  "var_en": ["Counter Bore", "C'Bore"],
  "scene": "工程图孔标注"
}
```

### 4.2 输出形态

- **中文上屏**：`沉孔`
- **英文上屏**：`Counterbore (GB/T 152.3)`
- **别名可用**：`Counter Bore` / `C'Bore`（兼容国际图纸习惯写法）

`to_english()` 按「当前领域优先 → 词频」排序返回全部匹配，
`english_of()` 返回最佳单条，两者供 UI 按需调用。

### 4.3 英文别名索引

英文索引同时收录**整句**、**单词**、**别名**：

```
"Counterbore"      → 整句
"counter" / "bore" → 单词级（支持模糊反查）
"Counter Bore"     → 别名
"C'Bore"           → 别名
```

用 `set` 去重，避免同一术语被重复计入。

## 五、数据持久化

### 5.1 SQLite 使用历史

```sql
CREATE TABLE usage (
    zh          TEXT PRIMARY KEY,
    count       INTEGER NOT NULL DEFAULT 0,
    last_used   REAL    NOT NULL DEFAULT 0,
    profession  TEXT    NOT NULL DEFAULT ''
);
```

采用 `INSERT ... ON CONFLICT DO UPDATE` 原子累加，支持连续上屏。

### 5.2 自定义词条

存于 `data/user/custom_terms.json`，加载时注入索引并标记 `custom=True`，
在排序中获得 +50 加成，确保用户自建术语优先出现。

## 六、与水杉输入法的对接

`lexicon.py` 提供 `export_rime_dict()`，输出标准 Rime `.dict.yaml`：

```yaml
---
name: zhiyu_mechanical
version: "1.0.0"
sort: by_weight
columns:
  - text
  - code
  - weight
...
螺纹孔	luowenkong	950
沉孔	chenkong	900
```

导入 Rime 用户目录即可由水杉输入法直接加载，
复用其成熟的输入法框架与词库调度机制。

## 八、后续可扩展方向

1. **C++ / TSF 外壳**：将引擎层用 C++ 重写并封装为 Windows TSF 输入法，
   直接对接系统输入法框架，无需模拟粘贴。
2. **候选窗跟随输入框**：通过 UI Automation 获取插入符位置，替代当前的光标跟随。
3. **词库云同步**：将 `data/lexicons` 与 `data/user` 接入云端，支持团队共享术语库。
4. **LLM 辅助扩展**：对新术语自动生成中英映射与释义，人工审核后入库。
5. **多音字与方言拼音**：接入 `pypinyin` 的 `heteronym` 模式，进一步提升召回。
