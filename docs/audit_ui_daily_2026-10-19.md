## 〇、结论先行（三句话）

1. **作为"专业词汇助手"它已经合格；作为"日常输入法"还差三块地板**：
   **没有中文标点**（写中文全是英文逗号句号）、**组合态按左右方向键会把拼音原文吐出来**、
   **CapsLock 打开时仍然出中文**。这三条不修，日常写字会觉得"这输入法没做完"。
2. **UI 按钮层最痛的不是"缺功能"，是"缺可达性"**：顶行 6 枚图标只有 17×17px（鼠标热区不足）、
   ✕ 点一下直接退出无确认、托盘右键没有任何菜单、没上屏的词没有"一键入库"的入口。
3. **体积/性能的大头各有一个，且都在意料之外**：体积最大项是 Qt6 三件套（26.9 MB，46%）里
   **本可删掉的 TLS/图像插件约 4.3 MB**；而内存/启动的最大单项是 **pypinyin（+49 MB / 118 ms）**，
   它只在"加新词"时才真正需要——**构建期把拼音写进词库**即可几乎白拿。

实测基线（本机，一次安装版 + 多次源码态）：

| 指标 | 现值 | 目标 |
| --- | --- | --- |
| 安装目录 | 56.0 MB / 190 文件 | ≤ 50 MB |
| 安装包 | 27 MB | ≤ 24 MB |
| 冷启动（进程起→CPU 静默） | **2.22 s** | ≤ 1.2 s |
| 常驻内存（12 s 后） | **217 MB** | ≤ 120 MB |
| 单键检索（1990 词条） | 0.19 ms（p95 0.23） | 维持 < 1 ms |
| 引擎初始化 | 537 ms（pypinyin 118 + 词库 112 + 索引/其它） | ≤ 150 ms |
| 通用词库预热 | 130 ms / +28 MB | 后台不变，占用 ≤ 12 MB |

分阶段归因（子进程实测，排除干扰）：

```
base        RSS  22 MB
+pypinyin   +118 ms  RSS  71 MB   ← 单项 +49 MB
+15 行业词库  +112 ms  RSS  77 MB
+通用词库 82k +114 ms  RSS 105 MB
```

## 一、UI 功能按钮审计（10 条）

> 顶行图标列现状：＋加词条 · 🏷行业 · ⒶAI · ⏸暂停 · Ⓘ关于 · ✕退出（均 17×17px）。
> 另有：托盘图标（仅双击=显隐）、4 个弹窗、首启引导、悬停说明卡、悬浮「译」钮。

- **U01 图标热区只有 17×17，日常会点空（P0，0.3d）**
  现状：6 枚图标固定 17px，横向间距 4px。问题：鼠标精细操作成本高，误点相邻图标（Ⓐ→⏸ 最易。
  ⏸ 一点就"打不出中文"）。方案：**视觉 16px、热区 26×26**（`setFixedSize(26,26)` + 内绘居中），
  图标列总宽从 ~126 → 180px（候选条上限 560 够用）；同时保留 hover 高亮与 tooltip。

- **U02 ✕ 单击直接退出，没有确认（P0，0.1d）**
  现状：`btn_close` → `quit()`，进程直接结束（钩子卸载、托盘消失）。问题：与 Ⓘ 相邻，
  误触即"输入法没了"，日常用户第一反应是以为崩了。方案：单击改为**托盘气泡提示 + 图标微抖**
  或弹一个 3 秒可撤销的小提示「已最小化到托盘，再点 ✕ 退出」；更简单可靠的是
  **✕ = 收起到托盘，退出走托盘右键菜单**（见 U03）。

- **U03 托盘没有右键菜单（P0，0.3d）**
  现状：v2.2「托盘净化」把菜单删了，只剩双击=显隐。问题：日常输入法用户 100% 会右键托盘找
  「设置/暂停/退出」，现在右键**无反应**，只能去点候选条上那排小图标——但候选条不常驻。
  方案：恢复**极简右键菜单**（5 项）：`暂停/恢复接管` · `显示候选条` · `快捷键速查` ·
  `打开配置目录` · `退出`。不做设置中心，不违背"净化"初衷。

- **U04 ⏸ 只切"接管开关"，缺"中/英"直切（P1，0.4d）**
  现状：⏸ = 全局暂停（等价 Ctrl+Space）。问题：日常写字最常做的是**中英切换**（写一句英文再切回来），
  而"暂停接管"语义是"我不用这个输入法了"，两者混在一起让用户不敢点。
  方案：⏸ 语义改为**中/英模式切换**（图标 ⏸→「中」/「英」徽标，戳一下切换，tooltip 说明），
  "暂停接管"下沉到托盘菜单。等价键仍是 Ctrl+Space。

- **U05 关于弹窗的唯一主动作是"导出水杉词库"（P0，0.3d）**
  现状：Ⓘ 里只有「导出水杉词库 / 打开导出目录」+ 版本号。问题：这是给 1% 用户的迁移功能，
  却占了 100% 用户唯一的"关于"入口；而**改快捷键、开机自启、查日志、反馈、检查更新**全都没有落点。
  方案：重排为四行按钮（2×2）：`快捷键速查`（I08）· `开机自启` 开关（I09）·
  `打开日志目录`（排障）· `导出词库`（保留但下沉为次级）；底部一行"检查更新"（F04 上线后启用）。

- **U06 🏷 行业弹窗对日常用户是"看不懂的选择题"（P1，0.3d）**
  现状：列出 15 个行业 + 每个行业的职业/职位。问题：日常用户不知道自己是"机械"还是"通用"，
  选错会让候选偏移；且没有"自动"。方案：**首项改为「自动（跟随当前软件）」**并默认选中，
  行业按场景探测自动切换；把"手动锁定行业"标注为"仅当自动判断不准时使用"。

- **U07 Ⓐ AI 弹窗把 base_url/model 直接摊在首屏（P1，0.3d）**
  现状：3 个输入框（接口地址/模型/Key）+ 开关。问题：日常用户被"接口地址"劝退；
  I11 已批"加获取地址"，但更该做的是**折叠高级项**：首屏只有「启用 AI 增强」开关 +
  「去申请免费 Key」一行链接 + 一个下拉预设（智谱/DeepSeek/本地 Ollama），
  接口地址与模型收进"高级"折叠区。

- **U08 加词入口太深，且不能"就地加"（P0，0.4d）**
  现状：只能点＋→手填中文/英文/简述。问题：日常最高频的加词时机是**"刚打出来的词不在库里"**，
  此刻要移动鼠标到候选条、点＋、再手打一遍。方案：**候选条右键菜单 + `Ctrl+Alt+Z`（可配）
  把"刚刚上屏的词"直接加入用户词库**（中文取自刚 commit 的候选/原文，英文取当前译法列），
  弹窗只作为"补英文/简述"的可选步骤。

- **U09 拖动钉住没有任何可见状态（P2，0.1d）**
  现状：拖动=钉住，双击=恢复跟随，只在 tooltip 里说。问题：用户拖完不知道"现在是不是不跟光标了"，
  下次打字发现候选条不在光标旁会以为坏了。方案：钉住时在顶行左侧显示一枚 **📌 小图标**
  （点击即恢复跟随），跟随态不显示。

- **U10 悬停说明卡只对鼠标、且信息偏专业（P2，0.3d）**
  现状：悬停 400ms 出卡（译法/标准号/推荐理由）。问题：① 纯键盘用户永远看不到；
  ② 日常用户看不懂"标准号/推荐理由"的取舍。方案：`F1`/`Ctrl+Alt+?` 对**当前选中项**出同一张卡；
  卡片首行给一句话人话（"这个零件在图纸上通常怎么写"），标准号降为次级灰字。

## 二、作为日常输入法：能力缺口（14 条）

- **DY01 没有中文标点（P0，1.0d）★ 最高优先**
  现状：`ime.py` 只处理 a-z 与组合键，`,` `.` `;` `:` `?` `!` 全部原样透传 → 写中文得到
  「你好,今天开会.」。问题：这是"能不能当日用输入法"的分水岭——中文写作里标点占比 ~8%。
  方案：中文模式下把 `, . ; : ? ! " ' ( ) 【 】` 映射为 `，。；：？！""''（）【】`，
  实现走"吞 keydown → 主线程 SendInput Unicode 上屏"，与上屏同一条通道（25 ms 级延迟，无感）。
  开关与边界：Shift+标点=英文标点；CAD 直通/暂停/URL 检测命中时**不转换**；`config.json` 可关。

- **DY02 组合态按左右方向键会吐出拼音原文（P0，0.3d）★ 真 bug**
  现状：`_decide()` 只处理了 ↑↓（移动候选）与 PageUp/Down；`←` `→` `Delete` `Home` `End`
  落进"标点等其它键"分支 → `commit_raw` 把 `chenkong` 直接打进文档。
  问题：改错别字时 100% 会按 ←，日常使用会频繁"吐出拼音"。方案：`←/→/Home/End/Delete`
  在组合态**先收掉组合（cancel）再放行按键**（不提交原文）；或 `←/→` 用于候选内移动光标
  （第一阶段先做"只 cancel"）。

- **DY03 CapsLock 打开时仍出中文（P0，0.2d）**
  现状：`_decide()` 只看 `_shift`，从不读 `VK_CAPITAL`。问题：用户开 CapsLock 想打纯英文
  （写型号、缩写），结果仍然被吞成拼音。方案：字母分支前置判断
  `GetKeyState(VK_CAPITAL) & 1` → 直通（并清空组合）；与 Shift 同语义。

- **DY04 英文/URL/路径/代码没有"自动直通"（P1，0.6d）**
  现状：要打英文要么按住 Shift 每个字母、要么 Ctrl+Space 切、要么空格直出原文（M3）。
  问题：写邮件、贴路径 `C:\Users\...`、输入 `https://`、邮箱、代码片段时，候选条会一直弹、还会吞键。
  方案：组合串**规则识别**（含 `.` `/` `\` `@` `:` `_` 或连续大写）→ 自动按"非中文意图"处理：
  候选条不出、空格直出原文、字母正常显示。识别只在"当前词"层面，不做全局状态机，误判可撤回。

- **DY05 中/英模式在候选条内不可见（P1，0.2d）**
  现状：只有托盘 tooltip 能看状态（I07 已做琥珀点）。问题：写字时视线在候选条上，
  看不见模式。方案：顶行 lead 区加**「中」/「英」小徽标**（11px，点击可切），与 U04 同一状态源。

- **DY06 候选条没有右键菜单（P1，0.4d）**
  现状：左键点胶囊=上屏；右键无反应。问题：日常输入法的右键菜单承担"删词/加词/固定/设置/翻页"，
  没有它所有纠错动作都无处安放。方案：右键菜单 4 项：`加入词库…`（U08）· `删除这个词`
  （写用户黑名单，记忆库不删）· `固定候选条/恢复跟随`（U09）· `设置…`（打开 Ⓘ）。

- **DY07 用户词没有"隐性学习"（P1，0.5d）**
  现状：只有显式加词 + usage 计数加权；用户打的词如果词库没有，永远只靠分段/前缀。
  问题：日常输入法靠"自动学新词"越用越顺手，我们越用越一样。
  方案：**同一串（中文≥2 字）上屏累计 3 次**且不在词库 → 自动进用户词库（低词频），
  设置里可关；不会污染专业候选（用户词单独一层、只在同拼音时出现）。

- **DY08 模糊音（已批 F06，P2，0.5d）** — 南方口音用户 z/zh、c/ch、s/sh、n/l、in/ing、en/eng。
- **DY09 自定义短语/简码（已批 F07，P2，0.5d）** — `dm→但明细表`，日常模板刚需；与 DY08 同批做。

- **DY10 数字/日期/算式快捷输入（P2，0.4d）**
  现状：无。问题：图纸写日期、写数量、算尺寸是每天的动作。方案：候选条内识别
  `rq→2026-10-19`、`sj→15:04`、`=3*4.5→13.5`、`dx→壹佰贰拾`，作为"第 0 位候选"插在句首，
  不命中不影响现有检索。

- **DY11 符号面板（P2，0.4d）**
  现状：工程符号（φ ± ° ≤ ≥ × ÷ Ⅰ Ⅱ ③ №）只能靠系统输入法或复制。方案：候选条内输入
  `fh`（符号）或 `Ctrl+Alt+.` 打开一个 6×8 的符号网格，点选即上屏；常用 12 枚置顶可自定义。

- **DY12 候选数量/字号/主题/候选条宽度没有可视化设置（P1，0.5d）**
  现状：全部要手编 `config.json`（`ranking.max_candidates`、`ui.font_size_zh`、`theme`…）。
  问题：日常用户不可能改 json，"候选太少/字太小"是最常见的抱怨。方案：Ⓘ 里加一页"显示设置"
  （候选数 5/7/9 · 字号 小/中/大 · 主题 浅/深/跟随系统（I05）· 条宽 窄/标准/宽）。

- **DY13 全屏应用/密码框缺少避让（P1，0.3d）**
  现状：任何前台都弹候选条。问题：全屏视频/游戏/远程桌面里候选条会闪；密码框里上屏中文会暴露。
  方案：① 前台窗口 = 全屏（`rcMonitor == rcWindow`）时**不弹条**（仍可上屏）；
  ② 焦点控件带 `ES_PASSWORD` 时暂停接管（`GetGUIThreadInfo.hwndFocus` + `EM_GETPASSWORDCHAR`）。

- **DY14 长句/语言模型：明确"不做"（P2，0 工作量，写进文档）**
  现状：整句分段=纯词典 DP，没有语言模型，句子语序会生硬（"我是工程师"能对，"今天下午三点开会"
  容易断错）。建议：**不做通用云输入/大模型整句**（与 B 端离线红线冲突、成本不可控），
  但在"未能完整覆盖"时给出 1 条"按 Q 译"提示（F12 已批），把长句交给 AI 按需触发。

## 三、体积优化（7 条）

> 现构成：Qt6*.dll 26.85 MB(47.9%) · 其它 dll 11.22(20%) · json 4.35(7.8%) ·
> pyd 3.72(6.6%) · exe 3.29(5.9%) · 通用词库 gz 3.24(5.8%，**两份**) · MSVC 1.80(3.2%)。
> Qt 官方 DLL 全带 CFG，UPX 自动跳过（预期），所以"再压 Qt"没有空间，只能"少带"。

- **SZ01 删掉 Qt 侧 TLS 后端（P0，0.2d，省 ≈ 0.64 MB）**
  `plugins/tls/*`：qopensslbackend 307 KB / qschannelbackend 242 KB / qcertonlybackend 102 KB。
  用途核查：QtNetwork 只被单实例 `QLocalServer` 用（本地命名管道，**不走 TLS**）。
  ⚠️ **`libssl-3-x64.dll` / `libcrypto-3-x64.dll` 不能删**——审计初期误判为 Qt 的 TLS 依赖，
  实测 `_ssl.pyd` 的导入表直接引用这两个名字（CPython 自己的 OpenSSL），AI 翻译走
  urllib https 全靠它；删了 = 大模型功能整体失效。这条记进红线：**动 DLL 前先查导入表**。
  *可选进阶（不建议本轮做）*：把单实例换成 Win32 命名互斥量 + 命名管道，可再删 Qt6Network
  1.67 MB，但触碰单实例红线，风险与收益不成比例。

- **SZ02 删掉用不到的 Qt 插件（P0，0.2d，省 ≈ 3.2 MB）**
  逐项核过（`plugins/` 目录明细）：
  · `imageformats` 1.74 MB（qjpeg 578 / qwebp 551 / qtiff 435 / qgif 47 / qico 46 / qicns 56 /
    qtga 37 / qwbmp 36）——托盘图标是代码绘制、引导页是 PNG（QtGui 内建解码），一个都用不到；
  · `platforms/qdirect2d.dll` 1.02 MB + `qminimal` 60 KB + `qoffscreen` 108 KB —— 只用 `qwindows.dll`；
  · `iconengines/qsvgicon` 71 KB（Qt6Svg 本就没打包）、`networkinformation` 77 KB、
    `generic/qtuiotouchplugin` 99 KB（无触摸场景）。
  方案：spec 里按文件名剔除，保留 `qwindows.dll`；`styles/qmodernwindowsstyle`（235 KB）建议保留
  （弹窗里的 QLineEdit/QScrollBar 观感），如要再省可测 Fusion 兜底。

- **SZ03 运行时不需要 pypinyin（P0，0.6d，省 ≈ 2.6 MB + 49 MB 内存 + 118 ms）**
  现状：不打包 `_PINYIN_FIX`/短语词典；词库 json **0/397 条带 pinyin**，所以每次启动都用 pypinyin
  给 1977 个词现算。方案（两步）：
  ① **构建期**把 `pinyin/abbr` 写进词库（`gen_engineering_lexicon.py` 已有 pypinyin，顺手落盘）；
  ② 运行时只在"用户加新词"时 `import pypinyin`（懒加载）。
  收益：冷启 −118 ms、RSS −49 MB；若第二步再进一步（用 20k 字单字拼音表替代），
  可整包移除 pypinyin（`phrases_dict.json` 2.43 MB + 包体）。

- **SZ04 数据不要"两份"（P0，0.3d，省 ≈ 1.7 MB 装后磁盘）**
  现状：`bootstrap()` 首次运行把 `_MEIPASS/data` **全量**复制到 `{app}\data`，其中
  `common/common.tsv.gz` 1.7 MB 是只读资源、用户永远不会改，而 `_internal/data` 那份仍然在 → 实际占两份
  （实测释放后 `{app}\data` = 2.3 MB；词库 604 KB 该留，通用词库 1.7 MB 不该留）。
  方案：**只释放用户会改的**（`config.json`、`lexicons/`、`phrases/`）；`common.tsv.gz` 与 `guide/`
  直接从 `_MEIPASS` 读（`config.common_dict_path` 已支持回退，只需删掉释放逻辑）。

- **SZ05 通用词库提供"精简版"（P2，0.3d，省 ≈ 1.6 MB）**
  82k 条对日常够用，但对"只装来画图"的用户是负担。方案：安装器加一个勾选项
  「精简词库（4 万条，省 0.8 MB）」，或干脆按 P04 冷热拆分后只带热点。**不推荐默认做**。

- **SZ06 词库 json 压缩（P2，0.1d，省 ≈ 0.4 MB）**
  0.56 MB → gzip 0.15 MB（加载时解压 ~10 ms）。收益小，等 SZ03 之后词库变"带拼音"再一起评估。

- **SZ07 UPX 对 Qt 无效，别再折腾（结论项，0 工作量）**
  3 个 Qt6 DLL 占 26.9 MB 且全 CFG，UPX 必然跳过；`--force` 会剥夺 CFG 保护（红线）。
  **明确接受**，把力气放在 SZ01/SZ02/SZ03/SZ04。
  ⇒ 安装包侧合计可省 **≈ 6.4 MB 目录（56.0 → 49.6）**，安装包 **27 → ≈ 24–25 MB**；
  再加 SZ04 的"不再重复释放"，**装完后实际占盘**再少 1.7 MB（56 + 2.3 → 47.6 + 0.6）。

## 四、算法优化（7 条）

- **AL01 拼音构建期化（P0，0.6d）**（= SZ03 的算法面）
  词库落盘 `pinyin/abbr`，运行时索引构建从"逐词 pypinyin"变成"读字段"。
  实测：词库加载 112 ms → 预计 15–25 ms；且不再需要在 import 期拉起 pypinyin。

- **AL02 行业词库按需加载（P1，0.4d，省 ≈ 6 MB / 20 ms）**
  现状：15 个行业 1990 条全量加载 + 全量建索引（含 15 套 `zh_index` 前缀）。
  方案：启动只加载 **当前行业 + `engineering.json` 共享层 + 通用层**；切行业时增量加载，
  并合并索引（`term_index` 是 defaultdict，增量安全）。风险：跨行业召回会短暂缺失 → 切行业后
  首次检索前完成加载（同步 < 30 ms，可接受）。

- **AL03 通用词库紧凑化（P1，0.8d，省 ≈ 15–20 MB）**
  现状：`dict[str, list[tuple[str,str,int,int]]]`，82k 条 → 每条约 350 B（含 str 对象与 tuple 开销）。
  方案：**单块 `array('i')` + 一段 `bytes` 文本池 + offsets**（或 `marisa-trie`，但引入依赖），
  查询仍走 bisect；预计 28 MB → 10 MB，且加载 114 ms → ~40 ms（免建 8 万个 tuple）。

- **AL04 打分预计算静态分（P2，0.5d）**
  现状：每个候选每次都算 `freq_score + profession + scene + software`（4 个查表 + 集合交集）。
  方案：`Term` 上缓存"与场景无关的静态分"（freq+software），只有 `history/custom/scene`
  每次叠加；1990 词 × 9 候选下意义不大，但配合 AL02 的增量索引能保持 O(1) 手感。

- **AL05 整句分段加"二元词频"（P2，1.0d，需人工校验）**
  现状：DP 只用 unigram raw freq（`(freq/4)^2.5` 近似），个别句子会断偏（"大帅个/大帅哥"）。
  方案：从 `usage.db` 的连续上屏对里统计 bigram，作为 DP 的第二项（权重 ≤ 0.3），
  先离线产出 200 条对照报告人工裁决，再上线。

- **AL06 拼音前缀 bisect 化（已批 P02，P2，0.3d）** — 域内 `term_index` 仍全表 startswith；
  1990 条 0.19 ms 够用，但算法与通用层不一致，扩容前统一。

- **AL07 检索结果宽度缓存（P1，0.2d）**
  现状：每次按键都重新 `measure()` 当前页全部候选（QFontMetrics 调用 × N）。
  方案：`{文本: 宽度}` LRU（上限 500），命中率 > 95%，省掉每键 0.1–0.3 ms 与字体度量调用。

## 五、性能优化（7 条）

- **PF01 冷启动 2.22 s → ≤ 1.2 s（P0）**
  分解：PyInstaller 引导 + Qt DLL 映射（~0.6 s）→ PySide6 import（234 ms）→ pypinyin（118 ms）
  → 词库（112 ms）→ 索引/其它（~200 ms）→ UI 30 ms。
  抓手：AL01/SZ03（−118 ms）、AL02（−90 ms）、Qt 插件裁剪（少映射 3 MB）、
  把 `TermEngine` 构造移出 UI 阻塞路径（先出托盘、再建引擎，首键前完成）。

- **PF02 常驻内存 217 MB → ≤ 120 MB（P0）**
  抓手：pypinyin 懒加载（−49 MB）、common 紧凑化（−18 MB）、行业按需（−6 MB）、
  Qt 插件少映射（−10~15 MB）。另需一次 **RSS 打点基线**（P06 soak 同源）。

- **PF03 事件轮询 25 ms → 自适应 12/25/100 ms（已批 P03，P1，0.2d）**
  现状：主线程恒 25 ms 轮询钩子队列 → 按键到候选最坏 25 ms（Sogou 约 8–12 ms）。
  方案：组合态 12 ms、空闲 100 ms、有弹窗 25 ms；e2e 的时延断言同步改为"组合态 < 15 ms"。

- **PF04 CAD 轮询别用 psutil（P1，0.2d）**
  现状：600 ms 一次 `psutil.Process(pid).name()`（构建 Process 对象 + 读镜像名）。
  方案：`QueryFullProcessImageNameW` 直取，或按 pid 缓存进程名（前台窗口切换时才重查）；
  单次 1–2 ms → 0.1 ms，且不再依赖 psutil（体积 −? 不大，但少一条链）。

- **PF05 首键延迟（P1，0.3d）**
  现状：钩子线程只入队，主线程消费；首个按键还要等 `system_ime_composing()`（imm32）。
  方案：把 `system_ime_composing()` 结果缓存 50 ms（同一组合串内不变），并在
  `prime_window()` 后预热一次引擎（空查询 `search("")`），让首键不承担首次分配。

- **PF06 长稳与内存曲线（已批 P06，P2，0.3d）**
  8 小时 soak + 每小时 RSS/句柄打点；判据：RSS 增长 < 15 MB、句柄增长 < 50。
  重点怀疑对象：悬停卡 QPixmap、弹窗复用、`_pages` 列表、hover 定时器。

- **PF07 高 DPI 重绘（已批 P07，P3，0.2d）**
  150%/200% 下 `bar.grab()` 耗时基线；配合 U01 的 26px 热区一起验（热区变大后重绘面积 +40%）。
