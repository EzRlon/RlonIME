## 一、功能能力（F 系列，15 条）

- **F01 译文对照预览（译前确认）**：现在翻译=直接替换，回退只能撤销。
  理由：工作文档里"替换即生效"有误覆盖风险。方案：悬浮钮单击先出「原文/译文」浮卡，
  Enter=替换 / Tab=仅复制 / Esc=取消（0.5d）｜**建议：采纳**。
- **F02 术语一致性检查（N2）**：框选整段英文 → 对照词库标出非标准译名并给建议。
  理由：直击"同一零件两种叫法比语法错误更严重"的红线；复用 to_english 反向对齐（1.5d）｜**采纳（P1）**。
- **F03 备份/恢复（F4）**：导出/恢复 zip（memory.db + custom_terms.json + config.json）。
  理由：记忆闭环的积累是本软件最大资产，换机即归零（0.5d）｜**采纳（P1）**。
- **F04 程序更新通道（F2）**：启动静默查版本 JSON，仅提示不强制。
  理由：修复无法触达已装用户；当前靠"重装找我"（1d + 服务端文件）｜**采纳（待签名后上线）**。
- **F05 词库热更新**：词库独立版本号（data/version.json），可单独下载替换。
  理由：词库迭代频率远高于程序；避免为加词重装（0.5d，依赖 F04 的下载器）｜**采纳（与 F04 合并做）**。
- **F06 模糊音开关**：z/zh、c/ch、s/sh、n/l、in/ing、en/eng。
  理由：南方口音用户打不出是硬流失点；通用输入法标配；引擎有前缀索引可低代价实现（0.5d）｜**建议采纳（P2）**。
- **F07 自定义简码/短语**：用户自建 `dm→但明细表` 类缩写与长文本。
  理由：老用户高频模板的自助通道；比改 json 友好（0.5d）｜**采纳（P2）**。
- **F08 词条导入/导出（团队共享）**：CSV/JSON 双向，含冲突提示。
  理由：设计部多人共享术语表是真实诉求（0.5d）｜采纳（P2，与 F03 合并入口）。
- **F09 记忆库管理界面**：列表/搜索/删除/纠正（现在只能删 db 文件）。
  理由：记忆库"只增不删"原则需给用户出口；否则错译无法清理（0.5d）｜采纳（P2）。
- **F10 未命中词反馈清单**：记录本地未命中输入，一键导出。
  理由：词库补强的数据来源，比拍脑袋列词准（0.3d）｜采纳（P2）。
- **F11 双击 Shift 切中英**：通用输入法肌肉记忆。
  理由：比 Ctrl+Space 更直觉；成本低（0.2d）｜采纳（P2）。
- **F12 分段句「按 Q 可译」轻提示**：整句候选上屏后 1.5s 内提示一次。
  理由：把记忆闭环引入口前移（0.2d）｜采纳（P3）。
- **F13 本地使用统计面板**：词频/命中率/行业分布（只本地）。
  理由：支撑"科学迭代"；隐私红线内（0.3d）｜采纳（P3）。
- **F14 双拼支持**：**不做**。理由：词库/测试/教学成本高，目标用户（CAD 工程师）
  主流全拼，收益/成本失衡。
- **F15 划词朗读/OCR 取词**：**不做**。理由：与"专业词汇助手"立意无关，属通用工具范畴。

## 二、交互与体验（I 系列，13 条）

- **I01 候选条宽度溢出治理（M1 同源根治）**：K 键复现：`折弯系数 K因子 卡扣 孔距 卡簧 块 开口销 开模 卡`
  共 9 枚胶囊，总宽超 560 → 序号被盖、末枚被切。理由：任何单字母（l/c/m/e）都会复现，
  观感即"坏"。方案：`_layout_chips` 前按"图标列+输入区+间距"算剩余宽度，**能放几枚放几枚**，
  溢出部分显式"…+N"并用 PageUp/PageDown 翻页；chip 宽度计算加序号实测宽度（0.5d）｜**必改**。
- **I02 溢出提示与翻页可见性**：现在翻页键存在但无视觉提示。理由：用户不知道能翻。
  方案：溢出时尾部加「…」徽标 + 悬停提示"PageUp/Down 翻页"（0.2d，随 I01）｜采纳。
- **I03 无匹配态措辞与动效**：现在「无匹配 · 空格直出」较生硬。理由：新用户会以为坏了。
  方案：改「未收录 · ␣ 直出原文」，配 120ms 柔和淡入（0.1d）｜采纳。
- **I04 译法行超长省略与完整展示**：长英文可能截断且无查看途径。理由：图纸标注需要看全。
  方案：elide + 悬停卡补全（hovercard 已有基座，0.2d）｜采纳。
- **I05 主题"跟随系统"**：现在固定浅/深手选。理由：SolidWorks 深色 + 系统暗色用户割裂。
  方案：theme=auto 读系统深色（0.3d）｜采纳（P2）。
- **I06 托盘单击=显隐候选条**：v2.3.1 双击=显隐；单击仍无动作。理由：普通用户肌肉记忆是单击。
  方案：单击与双击同语义（0.1d）｜采纳。
- **I07 暂停/直通状态可视化**：暂停时托盘图标无变化。理由：用户不知道"为什么打不出中文"。
  方案：暂停/CAD 直通时托盘图标叠半透明点 + tooltip 说明（0.2d）｜采纳。
- **I08 快捷键速查入口（F8）**：`show_hotkey_reference` 已存在但无调用方。理由：托盘菜单删除后
  老用户无法复查键位。方案：关于弹窗加按钮（0.1d）｜采纳（随清理包）。
- **I09 关于弹窗「开机自启」开关（F6）**：现只能重装时选择。理由：关闭自启是常见诉求。
  方案：读写 HKCU Run（0.2d）｜采纳。
- **I10 气泡/提示频率控制**：启动气泡每次启动都弹 4s。理由：打扰。
  方案：每天最多 1 次；异常提示 3s 自动收（0.1d）｜采纳。
- **I11 AI 未配置引导**：Ⓐ 弹窗仅提示"还没填 Key"。理由：目标用户不知道去哪申请免费 Key。
  方案：预设旁加一行"获取地址"文案（纯文本，不自动开浏览器）（0.1d）｜采纳。
- **I12 深色下悬浮卡对比度复核**：暗色主题下 hover 卡描边/背景对比未随主题校验。
  理由：盲区视觉细节影响专业感（0.2d，并入 I05 验证）｜采纳。
- **I13 欢迎引导的"键位手势图"**：现在只有三张截图 + 三行文字。理由：拼音数字选词/翻页手势
  需要一屏图示。方案：引导页加一张键位示意（0.3d）｜延后（P3）。

## 三、性能与稳定（P 系列，8 条）

- **P01 启动与首键延迟建档**：无启动耗时指标。理由：冷启体验决定第一印象；
  方案：启动打点日志（进程起→可输入）+ `scripts/bench_start.py` 基线（0.3d）｜采纳（P1）。
- **P02 域内前缀扫描 bisect 化**：`engine.search` 对 term_index 仍全表 startswith
  （1900 词无感，但算法与通用层不一致）。理由：一致性 + 未来扩词库不退化（0.3d）｜采纳（P2）。
- **P03 事件轮询空闲降频**：主线程 25ms 轮询恒定。理由：笔记本续航；空闲时 100ms、
  组合态 25ms 自适应（0.2d，需回归 e2e 时延项）｜采纳（P2）。
- **P04 通用词库冷热拆分（F10）**：全量 82k 常驻 +28MB。理由：老机器内存压力。
  方案：top 2 万常驻，其余首次未命中时后台补齐（0.5d，需保命中不退化）｜采纳（P2）。
- **P05 pypinyin 加载成本评估**：引擎初始化 25→82MB 的大头疑为 pypinyin 词典。
  理由：若可懒加载，冷启可省 0.2–0.4s（先测后定，0.2d）｜**先测量再裁决**。
- **P06 长稳（soak）测试**：无 8h 运行用例。理由：动画/提图对象复用不当会慢性泄漏。
  方案：soak 脚本 + 每小时 RSS 打点（0.3d，配合 P01）｜采纳（P2）。
- **P07 高 DPI 重绘基准**：150%/200% 缩放下候选条 grab 耗时无基线。理由：多屏混合 DPI 是
  真实工作台（用户刚报过多屏问题）。方案：3 档 DPI 基准脚本（0.2d）｜采纳（P3）。
- **P08 词库合并单文件**：**不做**。15 个 json 加载 <50ms，收益低风险无谓。

## 四、架构与工程质量（A 系列，9 条）

- **A01 panel.py 死代码归档**：968 行无人引用。理由：维护噪声与误读风险（0.1d）｜**采纳（P1，清理包）**。
- **A02 死参数/临时文件清理**：`--settings` 解析、`packaging/_b.iss`、`_installer_build.iss`、
  `scripts/scribble_*.py` 一类临时件。理由：交付卫生（0.2d）｜采纳（P1）。
- **A03 配置 schema 版本化**：无 `config_version`。理由：v2.2/2.3 已多次加字段，
  未来迁移只能靠"猜默认值"；加版本号+迁移器（0.3d）｜采纳（P2）。
- **A04 崩溃日志增强**：现有 crashlog 只有栈。理由：现场排查需要"当时在哪个软件/什么输入"。
  方案：附场景/输入长度/最后 200 条事件环（不含文本内容，守隐私）（0.3d）｜采纳（P2）。
- **A05 ime.py 拆分（钩子/状态机/定位）**：**延后**。理由：骨架文件改动风险高
  （历史事故全在此处），当前 783 行尚可维护，收益不抵风险。
- **A06 新增三条用例**：test_floatbtn（悬浮钮）、test_cad_passthrough（直通语义）、
  test_chip_layout（胶囊不重叠，用 rect 相交断言）。理由：M1/M2/M4 的回归护栏（0.4d，随施工）｜必须采纳。
- **A07 词库生成器加拼音一致性校验**：`_PINYIN_FIX` 与 pypinyin 结果逐词比对入库报告。
  理由：多音字错读会直接"打不出来"，已踩过（铣削/伺服）（0.2d）｜采纳（P2）。
- **A08 print→logging 分级**：现在各模块 print/stderr 混用。理由：排障与静默模式（0.3d）｜采纳（P3）。
- **A09 构建防呆**：build.py 在 `--clean`/复用 dist 目录时给出明确警告（本次两坑的护栏）（0.1d）｜采纳（P2）。

## 五、数据与词库（D 系列，7 条）

- **D01 通用词库英文反查（N6）**：现在英文反查只覆盖专业/共享层。理由：读英文资料时
  "plan→方案"是高频动作；top 2 万条 en 索引内存约 +2MB（0.5d，依赖 P04 拆分）｜采纳（P2）。
- **D02 CEDICT Top500 释义精修**：通用层直转释义偶有"木材纹理"式偏差。理由：释义是
  "英文翻译"体验的门面；只精修最高频 500 条回报最高（0.5d）｜采纳（P2）。
- **D03 多音字修正表外置**：`_PINYIN_FIX` 进 json，用户可增改（附 A07 校验）。理由：错读一旦
  发生用户只能"以为没这词"（0.2d）｜采纳（P2）。
- **D04 同音冲突审计**：输出"同拼音多词 + 权重排序"报告，人工裁决头部的 200 组。
  理由：v2.3 后词量 1200+，同音竞争决定首候选质量（0.3d）｜采纳（P3）。
- **D05 联想对自动挖掘**：从 usage.db 共现挖掘候选对，人工过白名单后并入 assoc。
  理由：手动维护 pairs 不可持续（0.3d）｜采纳（P3）。
- **D06 词库导入格式文档**：用户自建行业词库的 schema + 校验脚本（README 附录）。
  理由：开放性叙事，降低补库成本（0.2d）｜采纳（P2）。
- **D07 分段边界复核 20 例**：seg 用 raw freq 近似，个别句子会分偏（如 大帅个/大帅哥）。
  理由：A 类体验瑕疵，成本低（0.2d，人工清单+必要时调权）｜采纳（P3）。
